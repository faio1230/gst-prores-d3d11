# 設計

## 復号とメモリの流れ

`proresd3d11dec`は`GstVideoDecoder`としてProRes packetを受け取る。CPU側はframe／picture header、slice境界、各面の長さ、量子化行列と出力条件を検査し、GPU用のジョブ表を作る。CPUで画像を復号したり、通常出力を読み戻したりはしない。GPU側の処理は次の順序で同じD3D11 deviceへ投入する。

1. `prores_vld.hlsl`：sliceのDC・ACを可変長復号し、progressiveまたはinterlacedの逆スキャンを適用して係数バッファへ書く。
2. `prores_idct.hlsl`：逆量子化、8×8逆DCT、10／12bitへの丸め・クリップを行い、Y/U/VのGPUテクスチャへ書く。CPUジョブ表は配置・量子化値が変わるとdirtyになり、D3D11へのupload後にだけ解除する。
3. アルファがあれば別のCompute Shaderで復号し、Y/U/V/Aを標準`AYUV64`テクスチャへ詰める。アルファなしならplanarの3面をそのまま`GstD3D11Memory`として返す。

IDCTは1ブロック＝1 thread group。D3D11の1軸65,535 group上限を守るため、Xを最大65,535、Yを必要な行数とする2次元Dispatchを使い、`SV_GroupID.y × 65535 + SV_GroupID.x`からブロック番号を復元する。8192×8192・4:4:4＋alphaを仮定したDispatch算術ではIDCTが65,535×49、VLDが12,288×1、alphaが4,096×1、pack／RGBが各1,024×1,024で上限内。ただし8192²の実フレームを確保・連続復号できると検証したものではない。

## 非同期のVLDエラー検査

GPUのVLDはjob別エラーフラグを残す。フラグのstagingコピーを3面のリングで管理し、4枚目の投入前に最古を回収する。EOS/drainでは残りを回収し、flushing seekでは旧segmentの未回収結果を破棄する。破損を見つけても停止せず、GStreamer標準の`max-errors`（`GstVideoDecoder`のプロパティ）に従って報告する。GPU完了を待つ必要があるときだけ`Flush()`後に`Map(DO_NOT_WAIT)`を繰り返し、反復の間はGStreamerのD3D11 device lockを保持しない。10秒の期限と`GetDeviceRemovedReason()`の確認を設ける。

この方式では破損の通知が通常最大3フレーム遅れ、該当画像が先に下流へ渡る可能性がある。flushing seekで捨てた旧segmentの未回収エラーは報告しない。実際のdevice lostからの復旧は未検証。

## 破損フレームの扱い

ProResは全フレームがフレーム内で完結し、他フレームを参照しない。そのため、壊れたフレームがあっても後続フレームの復号は続けられる。

- **GPUで遅れて判明した破損**：該当フレームはすでに下流へ出力済みなので、報告だけして復号を続ける。
- **CPUのparserで判明した破損**：そのフレームだけを捨てて続ける。
- **報告の方法**：どちらも`GST_VIDEO_DECODER_ERROR`で`max-errors`に数える。GStreamer 1.28の既定値（-1）では停止せず、アプリが検知できるよう`STREAM/DECODE`のWARNINGメッセージをバスへ出す。`max-errors`を0以上にすると、その回数を超えた時点でERRORとして停止する。
- **非対応の形式**：クロマ形式、bit深度、ヘッダ版、4:2:2の奇数幅、alpha深度、slice寸法、capsとの寸法不一致は、最初の出力フレームより前に出れば`STREAM/FORMAT`で停止する。出力を始めた後に出た場合は、壊れたフレームとして扱う。
- **停止を続けるもの**：10秒のタイムアウト、Mapの失敗、device lostは破損とは扱わず、従来どおり停止する。

## 出力形式と色

| 条件 | GStreamer出力 | 値の詰め方 |
| --- | --- | --- |
| 4:2:2／4:4:4、10bit、alphaなし | `I422_10LE`／`Y444_10LE`、3面D3D11Memory | 16bit容器の下位10bit |
| 4:2:2／4:4:4、12bit、alphaなし | `I422_12LE`／`Y444_12LE`、3面D3D11Memory | 16bit容器の下位12bit |
| alpha8／alpha16 | `AYUV64`、1面`R16G16B16A16_UNORM` D3D11Memory | YUV10は`(v << 6) | (v >> 4)`、YUV12は`(v << 4) | (v >> 8)`。alpha8は`(a << 8) | a`、alpha16はそのまま |

`AYUV64`の4:2:2 U/Vは隣接2画素へ複製して4:4:4へ展開し、補間しない。出力capsに元深度を表す独自フィールドは付けない。必要なCPU転送は利用側が`d3d11download`を明示する。

ヘッダのmatrix／transfer／primariesをGStreamerの標準`colorimetry`へ写し、未指定の成分は入力capsから補う。YUV出力にRGB matrixを付けないよう、matrix値0と未指定値2はUNKNOWNとして扱う。limited rangeは保持する。planar 4:2:2は左寄せ`chroma-site=mpeg2`を付ける。色タグの変更、寸法変更、4:2:2／4:4:4／alpha付きへの形式変更ではcapsを再交渉する。4:2:2の奇数幅は拒否する。

`proresd3d11rgb`は同じD3D11 device上で、progressive・limited BT.709だけを`RGB10A2_LE`（planar入力）または`RGBA64_LE`（AYUV64入力）へ変換する。planar 4:2:2のU/Vは左寄せ位置を線形補間し、444は各画素の値を使う。alphaはstraight alphaとして保持する。BT.601やHDRをBT.709とみなして暗黙変換しない。

## インターレース

1 packet内の2 pictureを順に解析し、フィールド局所の行をTFFなら偶数→奇数、BFFなら奇数→偶数へ配置する。インターレース用の逆スキャンを使い、alphaも同じ行配置に従う。出力capsの`interlace-mode=interleaved`と`field-order`、バッファのINTERLACED/TFFフラグを設定する。デコーダーはデインターレースせず、`proresd3d11rgb`もインターレース入力を拒否する。
