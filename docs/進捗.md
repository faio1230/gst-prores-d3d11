- 係数完全一致をVLD／逆スキャンの合格条件にし、float IDCTとの差だけを10bit code value 1まで許容する。Vulkan版で観測した17〜31の差へ流用しない。
- GStreamerのI422_10LEは3枚のR16_UNORMであり、10bit値を16bit容器の下位bitへ保持する。実際にdownloadした全sampleでも最大差1を維持した。
- 実写では先頭2フレームだけの比較ではstaging再利用バグを見逃す。全50フレーム比較を回帰条件とする。色比較はクロマ位置を明示し、GPUの中央補間とCPUの既定左寄せを混ぜない。
- VLDの1-bit反復loadは4 fps台の主因だった。32-bit window化後に100 fps前後へ改善し、係数完全一致を維持した。
- DLL依存とFFmpegをPATHへ入れない検査により、完成経路がVulkan/libavcodecへ暗黙fallbackしないことを分けて確認した。

1. `present`通知前約201msと通知後約188msという別々の実写停止を観測。合成60fpsのOS未表示はGPU完了が次の表示更新より十分前の例と後の例が混在し、可視／最小化状態では分けられなかった。sink内部のwindow show/render、DWMのラッチ締切・flip queue・遮蔽を同時ETWで分け、4K60と実写の起動・seekで0欠落と短い最大間隔を同時に検証する。
2. 専用RGB D3D11Memory経路の長時間表示と4Kの稀なQoS欠落を切り分ける。IDCT配置キャッシュ後の通常10周×2試行はQoS 0、旧版とのOS捕捉付き交互2組でもQoS/OS未表示が少ないが、新版にも126枚のOS未表示が残る。早期GPU完了群と次の更新後完了群を、DWM token・flip採否・次Presentとの時刻順で追い、安定した0欠落と短い最大表示間隔を別素材・長時間でも検証する。CPU変換との差の製品許容差と実素材のクロマ位置を明確にし、内部GPU copy、他GPU、実際のdevice lost／タイムアウトも検証する。shader個別GPU時間は測定済みだが、それ以外の転送・同期・表示時間は別に扱う。device lostの強制再現はD3D11に安全な`RemoveDevice` APIがないため、ドライバ全体へ影響しない試験方法を先に設計する。
