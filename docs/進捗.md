# 純粋DX11実装の進捗

更新日：2026-09-22。基点は `8c47248`。goal全体は継続中。

## 現在地

- HQ / progressive / 4:2:2 / 10bit / alphaなしの完全なProResフレームをCPUで厳密に境界解析する。
- SM5でVLD、逆スキャン、逆量子化、float分離IDCTを行う。1080p/4Kの全係数はCPU参照と完全一致、画素差は最大1。
- `proresd3d11dec` がGStreamer poolの3面R16_UNORMへ直接書き、`I422_10LE(memory:D3D11Memory)` を出力する。通常経路に画像のCPU読み戻し、Vulkan、libavcodec、画像copyはない。
- 180フレーム×3回のEOS、4位置seek、再起動、色、停止・破棄後のbuffer寿命、6エラー経路を実機確認した。
- 180フレームwall throughputはRTX 3070で1080p 139.1 fps、4K 88.2 fps。正式な定常性能ではない。

## 判断根拠

- 係数完全一致をVLD／逆スキャンの合格条件にし、float IDCTとの差だけを10bit code value 1まで許容する。Vulkan版で観測した17〜31の差へ流用しない。
- GStreamerのI422_10LEは3枚のR16_UNORMであり、10bit値を16bit容器の下位bitへ保持する。実際にdownloadした全sampleでも最大差1を維持した。
- VLDの1-bit反復loadは4 fps台の主因だった。32-bit window化後に100 fps前後へ改善し、係数完全一致を維持した。
- DLL依存とFFmpegをPATHへ入れない検査により、完成経路がVulkan/libavcodecへ暗黙fallbackしないことを分けて確認した。

## 次の手順

1. 起動100回、seek 1000回、30分以上、複数instanceを自動化し、停止・device/pool寿命を検査する。
2. per-frame、p99、CPU/GPU負荷を取り、VLDエラーフラグreadbackを含む同期コストを分離する。
3. D3D11変換・合成・表示相当の下流を接続し、同一device、色、10bit維持、GPU copy回数を確認する。
4. 実写／カメラ由来HQ素材と対象GPUを用意して画質・互換性を追加検証する。未対応profileやinterlaceはそれまで明示エラーのままにする。
