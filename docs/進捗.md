# 純粋DX11実装の進捗

更新日：2026-09-23。限定対象の純粋DX11 pluginは実装済み。実素材と表示の採用検証は継続する。

## 現在地

- HQ / progressive / 4:2:2 / 10bit / alphaなしの完全なProResフレームをCPUで厳密に境界解析する。
- SM5でVLD、逆スキャン、逆量子化、float分離IDCTを行う。1080p/4Kの全係数はCPU参照と完全一致、画素差は最大1。
- `proresd3d11dec` がGStreamer poolの3面R16_UNORMへ直接書き、`I422_10LE(memory:D3D11Memory)` を出力する。通常経路に画像のCPU読み戻し、Vulkan、libavcodec、画像copyはない。
- 180フレーム×3回のEOS、4位置seek、再起動、色、停止・破棄後のbuffer寿命、6エラー経路を実機確認した。
- 最終CSO版の定常D3D11Memory供給は1080p 293.8 fps、4K 133.1 fps。GPU完了込みは255.7/102.2 fps、p99 4.49/11.63 ms。
- 4KをGPU完了込みで30分・182,520フレーム実行し、起動100回、seek 1000回、同一device 2instance、独立device 2プロセスも成功した。
- d3d11convertでRGB10A2 D3D11Memoryへ変換し、2入力d3d11compositorまでGPUメモリのまま接続した。検査download込み118.4 fps。
- Atomos収録の公開1080p/50 ProRes 422 HQ実写50フレームを、固定FFmpeg CPUと全画素比較しY/U/V各最大差1。camera recorderの512-byteフレームパディングを許容し、picture内部の境界検査は維持した。
- DJI Inspire 3の公開4K/24 ProRes 422 HQ実写129フレームも全画素比較でY/U/V各最大差1。先頭フレームのVLD係数1,658万個はCPUと完全一致した。
- 再利用したD3D11Memoryのstaging読み戻しが旧フレームを返す不具合を修正。DX11 UAV書込後にdownload必要フラグを設定する。
- GStreamer標準 `d3d11convert` の実写RGB10A2は、BT.709・中央クロマ配置のCPU変換比で1080p R/G/B最大差5/2/5、4K 6/2/5。中性3段では中間灰R/Bが期待514に対し512、白R/Bが1023に対し1021。10bit R16_UNORM正規化差と整合する。
- 純粋DX11 RGB Compute Shaderを `proresd3d11rgb` としてGStreamerへ統合。復号済みI422の整数コードを復元してBT.709 limited→fullへ変換し、RGB10A2の1面D3D11Memoryへ直接書く。中性3段は独立式と完全一致。公開実写1080p全50枚／4K全129枚も、GStreamer要素の全画素で中央クロマ条件の独立式と各R/G/B最大1 code、MAE約0.03。CPU `videoconvert` 比では最大3/2/2、4/2/3。EOS・seek・停止後のbuffer寿命を1080p/4Kで確認。素材のchroma locationは未指定なので、撮影時の色意図まで含む採用判定は継続。
- 実表示計測では合成60fpsの1080p 3試行×540フレームはdrop 0。4Kは9試行中1試行で単発263ms停止と14 drop。他の8試行はdrop 0。原因未特定。
- 4K60を段階別PTS付きで追加12試行したところ、予定6480枚のうち表示6478枚。sinkのdrop申告は0だが、2試行で各1枚が圧縮入力後・DX11出力前に欠け、QoS各1件を伴った。約23msの復号段階遅延が直前にあり、元の263ms停止は再現せず原因未特定。
- 段階別表示の再測定では1080p60合成1620/1620、Proton実写1080p50は450/450、slomo検査パターン4K59.94は1080/1080。DJI実写4K24は3試行1159/1161、追加6試行2320/2322で、各1試行の起動直後に2枚欠落した。最初のpresentが約362msへ遅れ、最大間隔110～111ms。明示prerollでも9試行中1試行で再現。sink QoSを止めると9試行3483/3483だが最大間隔101msとなり、無欠落と滑らかさは別条件。
- 公開DJI実写4K/24は3周387/387表示、slomo.tv検査パターン4K/59.94は3周360/360表示、ともにdrop 0。後者は実写ではない。
- 新しい `proresd3d11rgb` を実表示へ接続。BT.709タグ付き合成1080p60は3試行1620/1620枚。4K60は初回3試行1609/1620枚（sink drop申告0、QoSを伴う復号出力前欠落11枚）、追加6試行3240/3240枚。専用RGBの4K direct供給は107.8fpsだが、表示最大間隔は初回102.2ms。標準変換の同一タグ素材9試行は4860/4860枚で、今回の非交互比較では原因を断定しない。
- 4K60のqueue付き12試行で6468/6480枚。欠落試行はRGB出力とpresent要求の後に約109msの間隔があり、32 buffer queueが満杯になってdemux入力も約115ms停止した。queueだけでは防げない。decoder QoS無効の別12試行は6480/6480枚だが自然停止は起きず、有効性は未確定。sink入力へ120msを人工注入すると通常QoSはdecoder段階で13枚破棄、decoder QoS無効は540/540枚でも約127msの表示停止が残った。
- 専用RGBで公開Proton実写1080p50を表示すると通常3試行434/450枚、preroll 9試行1344/1350枚で、それぞれ起動時のQoS欠落を1試行再現。DJI実写4K24の3試行は1161/1161枚。色精度は全フレーム合格でも、実表示の起動・停止条件は製品採用保留。
- 検査専用の素通し計測要素でsinkへのpush入口と復帰を同一PTSで記録。人工120ms停止をpush 120.80msとして捉えた。公開Proton実写の通常12試行では1試行で先頭push 203.55ms、`present`通知後から復帰まで約188ms、その直後にdecoder QoS欠落17枚。preroll 12試行でも1試行にpreroll中のpush 213.94msと再生時1枚欠落があり、因果は未確定。合成4K60の別12試行は6480/6480枚で長い自然停止が起きず、根治判定ではない。
- PresentMon 2.6.0のOS表示記録をPID・QPC・PTSで照合。合成1080p60/4K60はGStreamer各1620/1620枚、QoS 0でも、seek境界を除く1602枚中それぞれ53/15枚にOS表示時刻がなかった。実写Proton1080p50は1797/1800枚、起動時3枚をdecoder QoSで失ったが、捕捉された内側1725枚は全てOS表示時刻あり。実写の別停止では先頭sink push 248msの約201msが`present`通知前、Present API最大0.58ms。前回の通知後188ms待ちとは位置が異なり、原因未確定。詳細は[実素材と表示検証](実素材と表示検証.md)。

## 判断根拠

- 係数完全一致をVLD／逆スキャンの合格条件にし、float IDCTとの差だけを10bit code value 1まで許容する。Vulkan版で観測した17〜31の差へ流用しない。
- GStreamerのI422_10LEは3枚のR16_UNORMであり、10bit値を16bit容器の下位bitへ保持する。実際にdownloadした全sampleでも最大差1を維持した。
- 実写では先頭2フレームだけの比較ではstaging再利用バグを見逃す。全50フレーム比較を回帰条件とする。色比較はクロマ位置を明示し、GPUの中央補間とCPUの既定左寄せを混ぜない。
- VLDの1-bit反復loadは4 fps台の主因だった。32-bit window化後に100 fps前後へ改善し、係数完全一致を維持した。
- DLL依存とFFmpegをPATHへ入れない検査により、完成経路がVulkan/libavcodecへ暗黙fallbackしないことを分けて確認した。

## 次の手順

1. `present`通知前約201msと通知後約188msという別々の実写停止を観測。PresentMon上のPresent API自体は短い。sink内部のwindow show/render、GPU完了、DWM表示、前面／遮蔽状態を同時ETWで分け、4K60と実写の起動・seekで0欠落と短い最大間隔を同時に検証する。
2. 専用RGB D3D11Memory経路の長時間表示と4Kの稀なQoS欠落を切り分ける。CPU変換との差の製品許容差と実素材のクロマ位置を明確にし、内部GPU copy、他GPU、device lost、動的caps/QoS、VLD/IDCT個別GPU時間も検証する。
3. 必要ならカメラ由来4K/60fps単一素材でも検査し、実写と60fpsの条件を同時に満たす。バイナリ素材はコミットせず、中間成果をgoal完了扱いにしない。
