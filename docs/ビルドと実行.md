# ビルドと実行

実機確認：Windows 11 x64、PowerShell 7、Visual Studio Build Tools 18 / MSVC 19.50.35729、Windows SDK 10.0.26100、同梱CMake。VS2022もスクリプトの分岐を用意しているが、このプロジェクトの実機ビルドはVS18のみ。

## 依存物

現在のビルドはGStreamer要素も生成するため、GStreamer MSVC x64のランタイムと開発SDKが必要。実機は1.28.2を使用。Windows SDK x64の `fxc.exe` でDX11 shaderをcs_5_0 bytecodeへ事前コンパイルする。既定配置は `C:/Program Files/gstreamer/1.0/msvc_x86_64`。別の配置は `./scripts/build.ps1 -GStreamerRoot 'D:/gstreamer/1.0/msvc_x86_64'` で指定する。プラグインを含む最短手順は[こちら](GStreamerプラグイン.md)。bootstrapはGStreamerを自動インストールしない。

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
./scripts/environment.ps1
./scripts/generate-media.ps1
```

bootstrapは2026-09-21のBtbN固定日付アーカイブのSHA256を検証する。FFmpeg 8.1.3 SDKは実行時パス互換のため `tools/ffmpeg-n8.1-latest-win64-lgpl-shared-8.1/` に配置するが、latestの内容を毎回取得する処理ではない。配布元が固定アーカイブを削除した場合は明示的に失敗し、別バージョンへ自動変更しない。アーカイブを同名でtoolsへ置いてもよい。

FFmpegのexeおよびavcodec/avutil/avformat DLLは、最初に試したlatestアーカイブと固定日付アーカイブでSHA256一致を確認した（`results/pinned-binary-equivalence.json`）。Vulkan-Headersはv1.4.325、commit `2e0a6e699e35c9609bde2ca4abb0d380c0378639` 固定。

比較・画質検査プログラムはCMakeからlibavformat/libavcodec/libavutilのMSVC import libraryにリンクする。プログラム起動時は該当SDKのDLLがPATHで優先される必要がある。純粋DX11 pluginはこれらへリンクせず、`use-d3d11-plugin.ps1` もFFmpeg/VulkanのPATHを追加しない。Pythonラッパーは子プロセスのPATHだけに設定する。直接起動するときは現在のPowerShellプロセスだけに設定する。

```powershell
$env:PATH=(Resolve-Path tools/ffmpeg-n8.1-latest-win64-lgpl-shared-8.1/bin).Path+';'+$env:PATH
./build/vs18/Release/prores_bench.exe media/synthetic-2160p60-hq.mov interop results/direct.csv 12 0 30
./build/vs18/Release/dx11_primitives.exe src/dx11_primitives.hlsl
```

既存GStreamerのbinを検証用FFmpegで上書きしない。FFmpeg9はABIの異なるDLLなので本計測器へ差し替えない。

## 性能測定

GPUを使う別の検証プログラムを同時に走らせず、電源設定・remote desktop・他アプリ・ドライバーを結果とともに記録する。

```powershell
python scripts/benchmark.py media/synthetic-1080p60-hq.mov media/synthetic-2160p60-hq.mov --modes cpu vulkan download cpu-d3d11 download-d3d11 interop --loops 12 --repeats 3 --out results/baseline-new
python scripts/benchmark.py media/synthetic-1080p60-hq.mov media/synthetic-2160p60-hq.mov --modes cpu-d3d11 interop --layers 4 --loops 12 --repeats 3 --out results/compose-new
python scripts/stress.py media/synthetic-2160p60-hq.mov --count 2 --layers 4 --mode interop --loops 20 --out results/stress-new
python scripts/benchmark-d3d11-plugin.py media/synthetic-1080p60-hq.mov media/synthetic-2160p60-hq.mov --loops 6 --repeats 3 --out results/d3d11-plugin-benchmark-new
python scripts/stress-d3d11-plugin.py media/synthetic-2160p60-hq.mov --count 2 --loops 6 --mode dx11-download --out results/d3d11-plugin-stress-new
```

引数の `--timeout` は各プロセスの全体上限秒、既定60。非常に長い実素材には増やす。失敗・timeoutはJSONの非zero returncodeに記録し、試行全体の終了コードも1とする。`.csv` はフレーム時系列、`.log` はdecoder/検証ログ、`.gpu.csv` はGPU全体サンプル、`.json` は集計・実行コマンド。異なる測定は別のoutへ保存する。

## 画素検査

画素検査のみNumPyが必要。既存Python環境に干渉しないよう必要に応じてvenvを作る。

```powershell
python -m venv tools/quality-venv
./tools/quality-venv/Scripts/python.exe -m pip install -r requirements-quality.txt
./tools/quality-venv/Scripts/python.exe scripts/quality.py media/synthetic-1080p60-hq.mov --frames 30 --native --out results/quality-hq-new.json
./tools/quality-venv/Scripts/python.exe scripts/quality.py media/synthetic-1080p60-4444-alpha.mov --frames 30 --native --out results/quality-alpha-new.json
```

`--native` を外すとFFmpeg CLI + hwdownloadで比較する。CLI経路と同期あり計測器は区別して記録する。今回の4444輝度不一致は5枚の同期あり検査では出ず、30枚に拡大すると同期ありでも再現した。`--threads 1`、`--avoid-host-import` もCLIの切り分けに使える。これらを変更した結果を同一条件の性能データへ混ぜない。

FFmpeg9によるCLI追試のみ必要なら `./scripts/bootstrap.ps1 -IncludeFFmpeg9` を使い、`quality.py --bin tools/ffmpeg-n9.0-pinned-win64-lgpl-shared-9.0/bin` で指定する。`--native` とFFmpeg9の組合せは使用しない。

## 終了・seek検査

```powershell
python scripts/validate.py --results results/baseline-new
```

失敗例を意図して残した正式baselineの成功記録だけを検査する場合は `--allow-failed` を明示する。失敗記録はvalidation.jsonに残り、成功へ書き換えない。

本リポジトリは検証プログラムの再ビルド手順を提供する。FFmpeg全依存ライブラリーをソースから再構築した再現性はまだ検証していない。製品化時の最小FFmpegビルドではProRes decoder/Vulkan hwaccel、MOV demuxer、avcodec/avutil/avformat、必要なSPIR-Vビルドツールを固定し、[BtbNビルド設定](https://github.com/BtbN/FFmpeg-Builds)と対応するFFmpeg configure条件を追跡する。
