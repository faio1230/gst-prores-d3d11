# M3：ProResアルファ拡張（回帰中）

2026-09-24、`proresd3d11dec`にアルファ8/16bitのDX11 Compute Shader復号を接続した。パーサが4番目の圧縮面を分離し、GPUでエントロピー復号したアルファと既存Y/U/Vを、GPU内で`AYUV64`の単一`GstD3D11Memory`へ詰める。CPU・FFmpeg・Vulkanへのfallback、および通常経路の画像CPU読み戻しはない。VLD結果の検査用コピーは従来の3枠非同期リングを維持する。アルファなし入力は従来の3面出力のままにする。

GStreamer 1.28.2のD3D11プールは`A444_10LE`などの4面planar形式を受理しないため、アルファ付き出力は`AYUV64`を選んだ。これはGPUの`R16G16B16A16_UNORM`テクスチャ1枚であり、各16bit成分の下位bitに10/12bitの符号値を入れる。4:2:2のU/Vは隣接画素へ複製する。出力capsに`prores-depth`と`prores-chroma-shift`を付け、後者はRGB変換時の中央補間に使用する。`proresd3d11rgb`はBT.709 limitedのアルファ付き入力をGPUで`RGBA64_LE`へ変換し、アルファを16bit全域へ正規化する。両形式は実際にGStreamer D3D11プールでUAV付き単一テクスチャとして確保できた。

検証素材は固定SDKで作った4444系のアルファ付き素材と、対応する422 YUV・444アルファの圧縮面を組み合わせた有効な422+アルファ素材。apco/apcs/apcn/apch/ap4h/ap4x×4:2:2/4:4:4×アルファ8/16bit、計24条件×2枚のCPU・DX11・Vulkan比較で、2,764,800画素のアルファ差0、Y/U/V差最大1。DX11の全Y/U/V係数7,372,800値はCPU参照と完全一致した。RGB変換はDX11出力のAYUV値から独立に計算したBT.709式と最大1（16bitコード）、アルファ差0。元のCPU-YUVとRGBを直接比べると、YUVの最大1コードの差が行列と16bitへの拡大で最大211コードに増幅されるため、RGBAに「CPUとの差1」を流用しない。詳細は`results/m3-alpha-centered-comparison-2026-09-24/summary.json`と`results/m3-alpha-coeff-all-2026-09-24.json`。

4K60×60枚の444/422・アルファ8/16bit計4素材では、全240枚・1,990,656,000画素のアルファ差0、Y/U/V差最大1。同素材は固定SDKのVulkan GPU復号でも全枚通過した。DX11 directの中央値は444/8bit 88.13 fps、444/16bit 85.04 fps、422/8bit 98.09 fps、422/16bit 95.88 fpsで、4条件とも60 fpsを超えた。Vulkanのwrapped/downloadも同一GPUで測定したが、測定境界が異なるため比率を同等性能の判定に使わない。根拠は`results/m3-alpha-4k-validation-2026-09-24/summary.json`、`results/m3-alpha-4k16-validation-2026-09-24/summary.json`、`results/m3-alpha-4k-direct-2026-09-24/medians.json`、`results/m3-alpha-4k422-direct-2026-09-24/medians.json`、`results/m3-alpha-vulkan-performance-2026-09-24/summary.json`。422素材の作成元とSHA256は`results/m3-422-alpha-fixtures-2026-09-24.json`。

1080p30×30枚の同4条件も追加し、全120枚・248,832,000画素のアルファ差0、YUV差最大1、固定SDK Vulkan全枚通過。DX11 direct中央値は444/8bit 126.73 fps、444/16bit 109.88 fps、422/8bit 144.55 fps、422/16bit 123.52 fps。同一RTX 3070上のVulkan wrapped/downloadを各3回測ったが、DX11 directとの境界差は上記と同じ。結果は`results/m3-alpha-1080-validation-2026-09-24/summary.json`、`results/m3-alpha-1080-direct-2026-09-24/medians.json`、`results/m3-alpha-1080-vulkan-2026-09-24/summary.json`。素材は固定SDKの`prores_ks`で作った444+アルファとM2の422基底を合成したもので、実写ではない。

HQアルファなしの旧M2採用版と新版を、同一素材・同一GPUで交互4組測定した。1080pの中央値は445.6085→445.874 fps（+0.060%）、4Kは260.800→260.791 fps（−0.003%）で、−3%ゲートを通過。旧DLLのSHA256はM2採用時の結果と照合済み。根拠は`results/m3-alpha-hq-direct-ab-2026-09-24/summary.json`。

ASanはアルファ専用4種×2,000変異を通過。旧形式の公開HQ779枚、破損・EOS・seek・RGB、およびM2の18条件ライフサイクルは回帰通過。アルファ入力でも直接D3D11MemoryとRGBA64経路のEOS×2、seek、バッファ保持、破損時の遅延検出を確認した。比較用の長いログは`results/m3-alpha-*`に保存した。

M2旧形式の18素材780枚を新DLLで再実行し、CPU-DX11全画素差最大1、Vulkan全枚通過、RGB式との差最大1で、EOS/seekの先行結果と整合した。GPUのY/U/V係数12,703,334,400値もCPUと完全一致し、画素差最大1。詳細は`results/m3-alpha-m2-validation-2026-09-24/summary.json`、`results/m3-alpha-m2-rgb-2026-09-24/summary.json`、`results/m3-alpha-m2-coeff-2026-09-24/summary.json`。

M1の旧422系11素材420枚も新DLLで再実行し、CPU-DX11全画素差最大1、Vulkan全枚通過、EOS/seek/RGB成功。製品VLD CSOで全420枚の係数3,988,684,800値もCPUと完全一致、画素差最大1。1080pの8素材は`results/m3-alpha-m1-regression-2026-09-24/summary.json`、4Kの3素材は`results/m3-alpha-m1-4k-regression-2026-09-24/summary.json`、係数は`results/m3-alpha-m1-coeff-2026-09-24/summary.json`。

公開追加素材：[Descriptの透明映像テスト素材](https://github.com/descriptinc/transparent-video-support/blob/main/prores-hdr-yuva-4444.mov)を個別に取得し、再配布せず`build/m3-public`に置いた。SHA256は`b089b55f9cf1d50860761ce7ad91f11bd8003d36133bbaee81510212a6aed024`。180×240、ap4h、yuva444p12le、BT.2020/PQ、31枚・1,339,200画素でアルファ差0、YUV差最大1。`d3d11download`の16画素幅への行パディングを比較ツールで除外して判定した。HDR色のRGB経路は現在のBT.709専用変換へ接続できず、これはM5で扱う。リポジトリにライセンス表示が見つからないため、利用はローカル検証だけとし、素材をコミット・再配布しない。これはカメラ実写ではなく独立制作の公開サンプルであり、実写アルファの代替とは数えない。結果は`results/m3-alpha-public-hdr-stride-2026-09-24/summary.json`。

10bit代表として、上記のap4h圧縮packetを無変換でapchへ再タグした8素材（422/444×alpha8/16×1080p/4K）も照合した。全360枚・2,239,488,000画素のアルファ差0、YUV差最大1、Vulkan GPU全枚通過。通常のapchエンコードや実カメラ由来を示すものではなく、FourCCに従う10bit復号経路の能力検査である。根拠は`results/m3-alpha-apch-validation-2026-09-24/summary.json`。

この10bit代表のDX11 direct中央値は、1080pでは444/8bit 126.85、444/16bit 109.59、422/8bit 145.18、422/16bit 122.78 fps。4Kでは同順に87.58、84.55、98.18、96.01 fpsで全条件が60 fps以上。固定SDK Vulkanも同一GPU・同一素材でwrapped/downloadを各3回測り全試行通過したが、DX11 directとの境界差は上記と同じ。結果は`results/m3-alpha-apch-1080-direct-2026-09-24/medians.json`、`results/m3-alpha-apch-4k-direct-2026-09-24/medians.json`、`results/m3-alpha-apch-vulkan-2026-09-24/summary.json`。最初に入力枚数より長い180枚/loopを指定した測定はEOSで無効になったため、素材の30枚/60枚に合わせて再測定し、無効ログは別保存した。

残るap4x/apco/apcs/apcnも、同じ圧縮packetのFourCCだけを変えた32素材として1080p/4Kで測定した。全16条件ずつのDX11 direct中央値は1080p 109.40～145.18 fps、4K 85.31～99.15 fpsで、4K60ゲート未達は0。固定SDK Vulkanは各素材でwrapped/download×各3回、計192試行すべてRTX 3070のGPU経路・指定枚数で通過。ap4h/apchの既測定分と合わせ、6 FourCC×422/444×alpha8/16の全24条件で1080p/4Kの速度とVulkan GPU復号を記録した。最低4K directはapch/444/alpha16の84.55 fps。再タグ素材は通常の各プロファイルで独立エンコードした品質やカメラ実績を示さない。根拠は`results/m3-alpha-aliases-2026-09-24/manifest.json`、`results/m3-alpha-aliases-1080-direct-2026-09-24/medians.json`、`results/m3-alpha-aliases-4k-direct-2026-09-24/medians.json`、`results/m3-alpha-aliases-vulkan-2026-09-24/summary.json`。

範囲外の`alpha_info=3`は、有効なMOVの先頭ProRes frameを1 byte変えた負例で、固定SDK CPUとVulkanの両方が0枚復号で拒否した。DX11プラグインは同じ値を`STREAM/FORMAT`として停止し、出力を作らない。固定SDKの負例は`results/m3-alpha-invalid-mode-2026-09-24/summary.json`、プラグインの破損・遅延検出を含む16例は`results/m3-alpha-invalid-mode-smoke.log`。
