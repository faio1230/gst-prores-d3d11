# M1：ProRes 422系4プロファイルのDX11拡張

2026-09-24、RTX 3070 / GStreamer 1.28.2 / 固定FFmpeg `n8.1.3-20260921`で検査。`proresd3d11dec`の422/10bit/progressive入力をapco（proxy）、apcs（LT）、apcn（standard）、apch（HQ）へ広げた。VLDの3面リングとGPUメモリ出力は維持し、Vulkan/CPU fallbackはない。DX11 IDCTの出力範囲はFFmpeg n8.1 [`proresdsp.c`](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavcodec/proresdsp.c)と同じ10bit limitedコード4～1019に揃えた。変更前はproxy/LTの極値でCPU比4 codeの差が出ていた。

## 素材と出所

- 固定SDK `prores_ks`で4プロファイル×2系統×30枚の1080p/30を作成。系統は`testsrc2`合成と、[Proton Camera公式サンプル](https://doc.proton-camera.com/docs/samples/)のカメラ由来SDR/REC709 HQからの再エンコード。後者は撮影時のproxy/LT/standard原本ではない。元ファイル`media/reference-proton-rec709-hq.mov`のSHA256は`e873a09632c5eb9c3d2d9902af1dd558e70c14d3a458437160a56d91975f03c4`。同ページは視聴・ダウンロードを案内するが、素材の再配布・派生物について明示的なライセンスを確認できない。原本・再エンコード物をGitや配布物へ含めず、内部検査だけに使用する。
- 新3プロファイルについて4K/60×60枚の合成素材を追加した。全素材の入力パス、FourCC、枚数、SHA256は`../results/profile-422-expansion-2026-09-24/fixtures.json`と`fixtures-4k.json`。生成手順は`../scripts/generate-prores-422-profiles.ps1`と`../scripts/generate-prores-422-4k.ps1`。実写由来4Kの新プロファイル素材は未取得。

係数検査のCSO経路ではVLDの**製品ビルド済みbytecode**を使用し、画素の検査用IDCTだけR16_UINT向けソースからコンパイルする。製品IDCT CSOはR16_UNORM向けなので、そのままR16_UINTへ結び付けると値が異なる。通常プラグインの画素精度は上記の全画素比較で別途確認した。検査器の画像readbackは検証専用であり、通常の`GstD3D11Memory`出力へ加えていない。

## 性能

HQ directの旧採用版（`b08e1d9`の独立ステージ。`77c9672`まで実装差分なし）とM1版を同一合成素材で交互4組比較。1080p中央値445.98→446.70 fps（+0.16%）、4K中央値261.36→261.24 fps（−0.05%）で、−3%の許容ゲート内。詳細は`../results/profile-422-direct-ab-2026-09-24/summary.json`。

| 新プロファイル | DX11 direct 1080p | DX11 direct 4K | Vulkan wrapped 4K | Vulkan download 4K |
| --- | ---: | ---: | ---: | ---: |
| proxy | 815.08 | 343.57 | 1522.84 | 201.07 |
| LT | 557.93 | 279.77 | 1363.64 | 198.02 |
| standard | 486.49 | 263.86 | 1255.23 | 199.07 |

単位はfps、各3反復の中央値。4K directはすべて60fps超。DX11はsteady direct、Vulkan wrappedはGPU画像のreadbackなし、Vulkan downloadはGPU完了と転送を含むため、同一測定境界の優劣比較ではない。1080pのVulkan値と全反復は`../results/profile-422-format-performance-2026-09-24/summary.json`。ここでの4K60は**復号供給性能**であり、実表示の欠落0を意味しない。

## 未達

本段階は422/10bit/progressive/alphaなしのみ。M0で見つかった422系FourCCの444・alpha、4444系FourCCの422/12bit、インターレース、色・途中形式変更は未対応で、goal全体は未完了。新プロファイルのカメラ収録原本、他GPU、最終の通常QoS/Present(0)表示も未検証。次はM2で、FourCCとクロマを分離し、10bit 444と12bit 422/444をD3D11Memoryへ出力する。
