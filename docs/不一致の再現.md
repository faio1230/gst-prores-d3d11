# 4444輝度不一致と初回停止の再現情報

## 4444出力の輝度プレーンが0になる

合成素材を生成してから実行する。

```powershell
python scripts/quality.py media/synthetic-1080p60-4444-alpha.mov --frames 30 --native --threads 1 --out results/repro-alpha.json
```

実測条件：FFmpeg n8.1.3-20260921、NVIDIA RTX 3070 / 591.86、Windows 11。素材とDLLのSHA256はresultsに保存。

- 0始まりのフレーム1、2、4、5…でYプレーンの2,073,600サンプル全てが0。30枚中20枚で観測。
- 同じ出力のU/VはCPU参照と最大1階調差、Aは一致。
- 自動スレッド数の30枚検査ではフレーム16のY全体が0になる例を記録。
- 自動スレッド数の5枚検査ではこの大差が出なかった。短い検査だけでは判定できない。
- `--native` はreceive後にAVVkFrameのtimeline semaphore完了を待ってからav_hwframe_transfer_dataを呼ぶ。単純な「CPUがGPU完了前に読む」仮説だけでは説明できない。
- FFmpeg CLIでも再現。9.0系CLI、threads=1、avoid_host_import=1の探索でも大差が残った。

これは **取得したraw出力に問題があることの確認**であり、ProRes compute本体、画像pool再利用、転送処理、ドライバーのいずれが原因かは未特定。D3D11 interopは最初のフレームの転送一致しか検査していないため、全フレームのdecode結果が正常だとは主張しない。次は各フレームのGPU画像をD3D11側から独立に読み戻し、転送前後とCPU decodeの三者比較を行う。

検査結果：`quality-alpha-native-t1-30.json`、`quality-alpha-native-per-frame.json`。各プレーンの `per_frame` に差と0サンプル数を保存する。スクリプトの終了コード0は「比較処理を実行できた」の意味であり、品質合格ではない。

## 初回フレーム停止

`baseline-final/synthetic-1080p60-hq-vulkan-2.json` の試行は最初のフレーム完了前に4分超停止した。CSV作成済み、内容とdecoder stderrは空。対象PIDの検証プログラムだけを終了した記録が `vulkan-startup-stall.json`。

単発の観測で、確定した最小再現条件はまだない。最新runnerには各試行60秒のプロセスタイムアウトを実装した。GPU処理の待機タイムアウトだけではlibavcodec内部の停止を中断できないため、最終pluginではこの問題を解消し、正常にpipelineを停止できることを確認する必要がある。
