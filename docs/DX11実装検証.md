# DX11でデコーダーを実装できるか

判定：**SM5で必要な基礎計算は実機で実行可能。完全なProResデコーダーとしての成立・速度・画の品質は未証明。** 現在の高速経路のデコードはVulkanであり、DX11ネイティブデコード済みとは呼ばない。

FFmpeg CPU/Vulkan比較の実施後に、DX11の基礎検証を追加した。デコーダー自作や移植を性能比較より先に始めていない。

## 実機で実行した内容

`src/dx11_primitives.cpp` / `.hlsl` をMSVCとD3DCompilerの `cs_5_0` でコンパイルし、RTX 3070のD3D11 feature level 11_0でDispatchした。

- ByteAddressBufferから任意ビット位置を読む8,192ケース（32 bit境界をまたぐものを含む）：CPU参照と全件一致。
- 8×8逆DCT：64個の基底入力と64個の擬似ランダム係数ブロックを倍精度CPUの数式と比較。最大誤差0.003902、平均絶対誤差0.000210。
- groupsharedとGroupMemoryBarrierWithGroupSyncを使う2段の分離変換。
- R16_UINT typed UAVの対応フラグを確認。

結果は `results/dx11-primitives.json`。独立した数式による逆DCT検証であり、FFmpegの逆量子化・丸め・クリップ・スキャン順・ProRes VLCを移植したものではない。許容差0.02はこのfloat基礎テスト専用で、ProRes画質の採用基準ではない。

## Vulkanからの置き換え

| Vulkan実装で使う表現 | D3D11案 | 確認状態 |
|---|---|---|
| u8/u16格納と物理バッファ参照 | ByteAddressBufferのuint load、mask/shift、32 bitオフセット | ビット抽出を実機確認。VLC全体は未実装 |
| push constants / specialization constants | constant buffer、シェーダーvariant | 合成と基礎テストで利用 |
| 動的な画像配列とnonuniform indexing | Y/U/V/Aへ固定UAV/SRVを割当、成分別Dispatch | 設計段階 |
| 共有メモリとbarrier | groupshared、GroupMemoryBarrierWithGroupSync | 実機確認 |
| VLD後のIDCTパス | UAVを解除し、別パスのSRVへ切替 | 基礎IDCTのみ確認 |
| Vk timeline、external memory | D3D11内部のコンテキスト順序、必要ならquery/fence | 既存の描画・転送検証で使用 |

共通GLSLヘッダーの64 bit型宣言を「全ての算術にネイティブ64 bit整数が必須」とは解釈しない。GPUアドレスを32 bitオフセットへ置き換えられる範囲を定め、4 GiB境界を超えるパケットを拒否する設計が候補。SM5には標準のwave/subgroup命令がなく、必要な協調処理は共有メモリへ置き換える。[Microsoft Compute Shader資料](https://learn.microsoft.com/en-us/windows/win32/direct3d11/direct3d-11-advanced-stages-compute-shader)の1024 threads/group、8 UAV等の上限内に収める。今回の基礎テストは64 threads/group。

## 完全デコーダーにする場合の順序

1. progressive 422 HQ、10 bit、アルファなしに限定する。FFmpegのdemuxを再利用し、フレーム/スライス境界・サイズ・量子化行列を厳密に検査するCPU parserを用意する。
2. SM5でDC/ACの可変長復号、run/level、逆スキャンを実装し、係数段階でCPU参照と照合する。破損入力による無限ループ・範囲外読み取りを防ぐ上限が必須。
3. 逆量子化と逆DCTを実装し、10 bitの丸め/クリップ条件を固定する。整数方式とfloat方式を比較し、今回のCPU/Vulkan差の原因も調べる。
4. D3D11テクスチャへ直接出力し、CPU uploadとVulkan interopの両方に対して転送・合成込みで比較する。
5. 効果と正確性が確認できたらLT/Proxy/Standard、4444/XQ、12 bit、alpha、interlacedの順に拡張する。互換性が未確認の入力は明示エラーとする。

FFmpegのshader/parserを翻訳・改変する場合は派生部分のLGPL表示とソース提供を維持し、元revisionと差分を追跡する。HLSLに変換しただけでライセンス条件が消えるわけではない。初回は浮動小数点数式の独立テストにとどめ、完全移植を完成済みとはしていない。

採用判断には実際の422素材、必要な同時再生数、画の許容差、複数ベンダーのGPUが必要。ネイティブDX11化は実装候補として残し、Vulkan経路の問題を隠す代替として急いで採用しない。
