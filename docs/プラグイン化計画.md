# GStreamerプラグイン化計画

利用先アプリを一旦外し、GStreamer上で動作する独立したGPUデコーダーを先に作る方針へ変更した。2026-09-22時点で、実験版 `proresvkdec` のDLL、再現手順、実パイプラインの検査を実装した。現在の契約と検査結果は[実験版プラグイン](GStreamerプラグイン.md)を参照。

最終目標は**純粋なDX11デコードとGPUメモリのままの出力を両立したGStreamerプラグイン**。両方とも必須であり、Vulkan＋CPU読み戻しの実験版を完成としない。初版の出力はsystem memoryであり、D3D11MemoryやCPU fallbackは実装していない。422画素差・実素材・表示を含む実用性の確認も引き続き必要である。

## 最終到達条件と実装順序

1. progressive ProRes 422 HQ / 10bitを最初の対象とし、フレーム・スライスの解析と境界検査を行う。既存のCPU/Vulkan経路を正確性と性能の比較用に保持する。
2. DX11 Compute ShaderでVLD（DC/ACの可変長復号）、逆スキャン、逆量子化、逆DCT、丸め・クリップを実装し、係数と画素をCPU参照と照合する。完成経路の復号処理はVulkanを呼ばない。CPUでの入力解析・GPUへの圧縮データ投入・制御は許容し、画像のCPU復号で代替しない。
3. 復号先をD3D11テクスチャとし、GstD3D11Memoryの所有権・pool・同期・capsを実装する。通常出力経路は復号画像をCPUへ読み戻さない。画質検査用の読み戻しは通常経路から分離する。GPU内コピーも実測・明示し、GPUメモリ出力だけを根拠にゼロコピーとは呼ばない。
4. GStreamer下流のD3D11要素まで接続して色・精度・資源寿命を検証し、seek/flush/EOS、複数デコード、合成・表示込みの性能を評価する。DX11単体で動作・配布できることを確認する。

主実装はこの順序で進める。VulkanからD3D11への共有経路は比較・切り分けに必要な範囲で使い、そのプラグイン化をDX11開発の必須前提にはしない。DX11で成立しない条件が判明した場合は根拠と未達条件を報告し、最終目標をVulkanへ自動変更しない。

## 採用ゲート

1. 実素材の対象プロファイル、解像度、fps、同時再生数を固定する。CPU参照との差の原因と許容基準を合意し、4:2:2/4:4:4、range、10/12 bit、必要なalphaを検証する。
2. 初回停止とCLI読み戻し異常を最小再現に分ける。ドライバー/FFmpeg版/スレッド/同期を変え、起動100回、seek1000回、30分以上の連続再生で無停止を確認する。
3. 目標のフレーム予算に対し、転送・色変換・合成・表示込みでp99とseek後復帰を測る。最大fpsが高いだけでは合格にしない。暫定比較目標はCPU経路に対して20%以上の改善、または同等の供給安定性でCPU負荷を十分減らすこと。これは提案値であり利用先仕様ではない。
4. 実際のD3D11コンポジター相当の多入力・単一deviceで検証する。Intel/AMD/NVIDIAの対象GPUごとに能力検査とfallbackを確認する。
5. DX11ネイティブのGstVideoDecoderとD3D11Memory出力で、以下のイベント/資源寿命の試験を通す。Vulkan実験版の成功を最終経路の合格とみなさない。

## 要素の契約案

最終要素の仮称は `proresd3d11dec`、GstVideoDecoder派生。既存の `proresvkdec` は比較用として区別する。独立DLLとしてアプリと別リポジトリで提供する。最初のrankはNONEまたは明示指定のみとし、CPU `avdec_prores` を全環境で自動置換しない。

入力は `video/x-prores`、demux済みの1フレーム/バッファを原則とし、実際のqtdemux caps（variant、幅、高さ、fps等）を確認してsink templateを確定する。MOVのdemux、ファイルアクセス、LTC同期は要素へ持ち込まない。破損フレームの長さ・slice数を検査し、AVPacketのpaddingと所有権を保証する。

出力要件は `video/x-raw(memory:D3D11Memory)`。422/10 bitの保持、RGB変換が必要な場合の精度・色域・range・alphaの契約を別々にする。GStreamerが表現できるformatとGstD3D11Memoryのプレーン構成を実際に検証するまでは、独自の3枚R16テクスチャをそのまま標準capsと名付けない。8 bit BGRAへの暗黙の精度低下は行わない。

最終経路でCPU/Vulkanへの暗黙のfallbackは行わない。未対応入力・GPUは明示エラーとする。CPU比較経路は独立して選択し、その成功をDX11デコード成功として扱わない。

## 時刻・メモリ・同期

- PTS/duration、segment、discontinuityをGstVideoCodecFrameとGPU処理の対応で維持する。入力DTSとraw出力の時刻の契約を区別する。タイムベースを明示変換し、欠損時刻を未定義のまま勝手に補わない。
- compressed GstBufferは解析・GPU転送に必要な間保持する。D3D11リソースとGstBufferの寿命を参照カウントで管理し、GPU処理と下流の読み取りが終わる前にpoolを再利用しない。FFmpeg比較経路ではAVPacketのpadding・AVFrameの寿命を別途保証する。
- downstreamのGstD3D11Deviceをcontext/queryで取得し、DX11復号と下流で共有する。Vulkan比較経路を接続する場合に限りLUID一致とAPI間共有を検査する。デバイス不一致は明示エラーとする。
- 初版はcopyと完了待ちを明確にした経路を使用する。次に3〜4枠程度のbounded poolで非同期化し、decode完了・D3D11読取完了の両方をslot返却条件とする。API間のmutex/fenceとGStreamer streaming lockの取得順を固定する。
- 初回の読み戻し検査は開発用オプションへ分離する。実運用で毎フレームCPUへの確認転送を行わない。

## イベントと異常終了の試験

| 入力/操作 | 期待する動作 |
|---|---|
| EOS | decoderをdrainし、最終フレーム完了後にEOS。フレームを残したままdeviceを破棄しない |
| FLUSH_START | 新規投入を止め、待機を解除できるようにし、古い世代のフレームを下流へ出さない |
| FLUSH_STOP / seek | 復号状態をリセットし、segmentと世代を更新。旧GPU処理を安全に回収し、新時刻の出力を開始。FFmpeg比較経路ではavcodec_flush_buffersも実施 |
| caps変更 | 旧poolの参照が全て返るまで保持し、新poolを確保。未対応変更は明示エラー |
| 入力破損/読み込み失敗 | GST_ELEMENT_ERRORへ原因を伝搬。無限待ち・黙示的な黒フレームにしない |
| PAUSED→READY→NULL | 処理投入を停止し、GPU待機と下流のbuffer保持を考慮してpool・texture・deviceを安全に解放 |
| device lost / timeout | pipelineを終了可能にする。プロセス再起動が必要なdriver問題と要素のエラーを区別 |

GstHarnessまたは独立pipelineで実時間再生、ランダムseek、逆方向seek、EOS中のflush、複数instance、drop/QoS、起動失敗、下流による長時間buffer保持を検証する。今回のlibavcodec単体のseek/EOS確認をこれらの代替にはしない。

## 必須のDX11 backend

`proresd3d11dec` または明示backendプロパティとして独立させ、同じcaps/PTS/所有権契約を使う。最初はprogressive 422/10 bitの限定サポートを宣言し、4444/alpha/12 bitを対応済みにしない。CPU解析→SM5 VLD→逆量子化/IDCT→D3D11 textureの経路で比較し、Vulkanに依存しない実行・配布を確認する。

利用先アプリへの導入は、このリポジトリから配布するpluginと実行例を使う別工程。利用先のLTC、playlist、Spout、fullscreen制御を本pluginへ移植しない。
