# M2：ProRes 4:4:4・12bitのDX11復号

2026-09-24、RTX 3070 / GStreamer 1.28.2 / リポジトリ固定FFmpeg `n8.1.3-20260921`で検証。alphaなし・progressiveのM0交差8条件を追加した。FourCC（apco/apcs/apcn/apchは10bit、ap4h/ap4xは12bit）とフレームヘッダーの422/444を独立に扱う。入力解析、GPU VLD・逆スキャン、逆量子化・逆DCTから3面の`GstD3D11Memory`出力まで純粋DX11で行い、CPU/Vulkanへのfallbackはない。VLDの3面リングは維持した。

## 実装範囲と素材

| FourCC / クロマ / 深度 | 出力format | RGB要素の入力 |
| --- | --- | --- |
| apco/apcs/apcn/apch / 444 / 10bit | `Y444_10LE` | BT.709なら`RGB10A2_LE` |
| ap4h/ap4x / 422 / 12bit | `I422_12LE` | 同上 |
| ap4h/ap4x / 444 / 12bit | `Y444_12LE` | 同上 |

各formatは3面の`R16_UNORM`テクスチャとtyped UAVを使う。bit値は16bit容器の下位に格納する。4:4:4のクロマはマクロブロックあたり4ブロック、4:2:2は2ブロック。IDCTはFFmpeg n8.1の[ProRes DSP](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavcodec/proresdsp.c)と同じ出力制限（10bit: 4～1019、12bit: 4～4091）へ揃えた。RGB要素は422では中央クロマ補間、444では各画素のクロマを使い、BT.709 limitedからfull-range RGB10A2へ変換する。非BT.709は現状明示的に拒否する。

固定SDKの`prores_ks`で8条件×1080p30枚と8条件×4K60枚を生成し、さらに公開カメラ素材を再符号化した1080p30枚をapch/444/10bitとap4h/444/12bitへ追加した。計18素材・780フレーム。元は[Proton Camera公式サンプル](https://doc.proton-camera.com/docs/samples/)で、`media/reference-proton-rec709-hq.mov`のSHA256は`e873a09632c5eb9c3d2d9902af1dd558e70c14d3a458437160a56d91975f03c4`。これは撮影時の4444原本ではなく、元の10bit HQを再符号化したもの。公式ページで再配布・派生物ライセンスを確認できなかったため、映像ファイルはGitへ含めず内部検査に限る。`prores_ks`の受入画素形式は10bitのみなので、12bit出力条件も10bit原画像からの符号化であり、12bit全階調を独立には網羅していない。

素材のパス・FourCC・SHA256・枚数は[`fixtures.json`](../results/prores-m2-2026-09-24/fixtures.json)、[`fixtures-4k.json`](../results/prores-m2-2026-09-24/fixtures-4k.json)。RGB用には画素を再符号化せずMOV色タグだけBT.709にしたコピーを用い、対応とSHA256を[`fixtures-rgb.json`](../results/prores-m2-2026-09-24/fixtures-rgb.json)へ記録した。生成は[`generate-prores-m2.ps1`](../scripts/generate-prores-m2.ps1)で再現できる。

## 残る範囲

M2はalphaなし・progressive・偶数幅での採用。GPU alpha復号とRGBA出力、TFF/BFF、端数寸法、色空間全般、途中形式変更、別GPU、最後の通常QoS/Present(0)実表示は未達。422+alphaの有効fixtureも未確保で、FFmpeg Vulkan可否を推定で対象外にしない。次はM3として8/16bit alphaをGPUで復号し、alpha付きD3D11MemoryとRGB alphaを検証する。
