# M5：色タグ・端数寸法・途中形式変更

2026-09-24。固定FFmpeg SDK（n8.1.3-20260921）のCPU復号を画素基準とし、GStreamer 1.28.2／RTX 3070の単一パイプラインで検査した。再現用の動的全画素比較は[`check-m5-dynamic.py`](../scripts/check-m5-dynamic.py)、集計は[`summarize-m5.py`](../scripts/summarize-m5.py)、判定値は[`summary.json`](../results/m5-2026-09-24/summary.json)。詳細ログと中間rawは`build/m5-probes/`にのみ置き、`results/`へは保存しない。

入力素材はM0の[`probe-prores-feature-matrix.ps1`](../scripts/probe-prores-feature-matrix.ps1)で作成した固定fixtureで、判定JSONにSHA256を記録する。BT.709付き奇数幅RGB検査は、`ap4h-odd.mov`を固定SDKの`ffmpeg.exe -c copy -color_primaries bt709 -color_trc bt709 -colorspace bt709`でMOVへ再タグ付けして行った。画素自体は変更していない。

## 実装と判定

- ProResヘッダーのmatrix／transfer／primariesをGStreamerの標準colorimetryへ写し、未指定の成分だけ入力capsから補う。limited rangeを維持する。BT.601=`bt601`、BT.709=`bt709`、BT.2020=`2:6:5:7`、PQ=`bt2100-pq`、HLG=`bt2100-hlg`を出力capsで確認した。BT.2020の数値表記はlimited／BT.2020 matrix／BT.709 transfer／BT.2020 primariesの組合せ。5タグ各2枚を固定SDK CPUと全Y/U/V画素比較し、最大差1 code。5タグを途中で切り替える10枚の単一パイプラインと、標準`d3d11convert`経由のRGBA64_LE出力がEOSまで通った。
- 4:2:2は偶数幅のまま、4:4:4は奇数幅を許容する。318×178の4:2:2と319×179の4:4:4で、SM5係数不一致0、全画素最大差1 code。319×179のBT.709 4:4:4は`proresd3d11rgb`のRGB10A2_LEまで独立式で全画素最大差1 code。奇数幅4:2:2はparserが明示的に拒否する。16bit planar形式の奇数幅ではGStreamerの4byte整列row paddingを比較器が除外する。
- `concat ! proresd3d11dec ! d3d11download ! video/x-raw ! multifilesink`の単一pipelineで、色タグ5条件10枚、解像度320×180→318×178の4枚、319×179の4:4:4を2素材4枚、`I422_12LE→Y444_12LE→AYUV64`の6枚を検査した。合計24枚すべてでcaps順・EOSと固定SDK CPU対DX11の全画素を照合し、YUV最大1 code、16bit alpha差0。色・解像度・形式の各途中変更は、標準`d3d11convert`からRGBA64_LEへつないだ経路でもEOSを確認した。通常出力は最後までD3D11Memoryで、CPU転送は検証用に明示した下流要素だけで行う。
- 既存のEOS/seek、buffer寿命、ソフトウェアadapter拒否、インターレース4条件をsmokeで回帰。新しい端数寸法2素材を含む6素材×4,000件＝24,000件のMSVC ASan変異も実施した。これらは決定的テストであり、任意bitstreamの安全性を保証しない。

## 限界

`proresd3d11rgb`は引き続きprogressive・limited BT.709専用で、BT.601等は暗黙変換せず拒否する。標準`d3d11convert`のBT.2020/PQ/HLG出力はcaps・EOSまでの確認であり、HDR→RGBの数値精度や表示機器の色管理は未検証。画面キャプチャは合格条件とせず、実表示QoS／Presentの別検査も未達。M5の画素・caps検証を通っても最終goal全体の完成とはしない。
